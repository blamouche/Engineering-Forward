# The dissolving boundary

*Decision models go open-source, agents learn to talk to each other across product lines, and the walls that separated AI products start coming down.*

Supersonic Labs released Julia 1 last week. It is a 144-million-parameter model that runs entirely on CPU — about five decisions per second on a Samsung tablet. It does not generate text. It makes decisions: yes or no, urgent or not, safe or risky. If that sounds familiar, it should. Julia 1 mimics the architecture of TypeSafe's Jev, the classification model that has dominated AI engineering discussions since its launch. The difference is that Julia 1 is open-source, built independently on multilingual mmBERT-small, and costs nothing to run. The decision layer that Jev pioneered as a commercial product now has a free, portable alternative that runs on the device in your pocket.

The same week, Matt Van Horn shipped Agent Tincan. It lets agents from different products — Grok Bot, Meta's Muse, OpenAI's Codex, Claude Code, ChatGPT — ask each other for help through a Tailscale-hosted relay. Grok Bot can ask Muse to call a restaurant. Any agent can retrieve an old Claude chat. The reply travels back without the user becoming the copy-paste layer. The tool is simple, hosted on a personal network, and requires one always-on machine. It is also the first practical demonstration of agents communicating across product boundaries that were supposed to be competitive moats.

[The good enough threshold](https://engineeringforward.substack.com/p/the-good-enough-threshold) described how standard models crossed a competence line and shrank the frontier's premium from 53 to 45 percent of AI spend in one month. The dissolving boundary is the next chapter. When the decision layer is free and agents can talk to each other across products, the walls between AI platforms stop being technical barriers and start being policy choices.

## The decision layer goes portable

Jev's economics were already disruptive. At 4.2 cents per million input tokens with free output, it made judgment calls — email classification, content moderation, urgency assessment — economically viable at volumes no LLM could match. [The adapter economy](https://engineeringforward.substack.com/p/the-adapter-economy) described how this decision model filled the gap between deterministic code and generative models. Julia 1 takes the same logic and removes the price tag. A 144-million-parameter model running on CPU, making five decisions per second on consumer hardware, means the decision layer is no longer a service you buy. It is a component you download.

TypeSafe and OpenRouter responded by shipping jev-router, a cache-aware router that uses Jev to score a request before any LLM call, choosing the model and reasoning effort to balance quality, speed, and cost. The routing decision — which model should handle this request — moves from a general LLM burning tokens to discover the answer, to a purpose-built model that scores the request in milliseconds. The economic logic compounds: a decision model that costs near-zero routes traffic away from models that cost real money, and the savings accrue with every request.

Privatemode demonstrated a different path. By prompting GLM-5.3-Flash to imitate Jev's decision system — making the first output token answer the question — a single forward pass produces a typed decision. It is a prompting technique on a standard LLM, not a purpose-trained model, so it remains several times more expensive than Jev. But it shows that the decision-layer concept is propagating faster than any single product can contain it. When the same architectural pattern appears as a commercial product, an open-source clone, and a prompting technique within the same week, the pattern has escaped the product. ByteByteGo's EP227 laid out nine use cases where Jev replaces LLM calls — model routing, guardrails, gating tool calls, triage, reranking, evals, bulk labeling, real-time decisions, and confidence gates. Every's deep dive walked through the practical decomposition: break "is this email urgent?" into discrete checks the model evaluates separately and you combine in code. The 10-second rule — if a judgment call would take a human less than ten seconds, a decision model should handle it — is becoming common knowledge. The open-source version means the rule now applies to anyone with a tablet.

## Agents without walls

Agent Tincan's significance is not the tool itself. It is the assumption it makes: that agents from different companies should be able to talk to each other. The current AI market is built on the opposite assumption. Each lab — OpenAI, Anthropic, Meta, xAI — builds agents that operate within its own ecosystem, using its own tools, accessing its own data. The moat is the closed loop. Agent Tincan treats the closed loop as a problem to be solved with a relay server and a Tailscale network.

The use cases are specific and revealing. Grok Bot asks Muse to call a restaurant — because Muse has phone-call capabilities that Grok Bot lacks. Any agent retrieves an old Claude chat — because Claude's conversation history has value beyond Claude's own agent. The user stops being the copy-paste layer between products that were never designed to share. The companies that refuse interoperability will face the same pressure that walled-garden internet services faced when the open web proved more useful than any single portal.

Google's REST-to-MCP conversion accelerates this opening. Google Cloud API Gateway can now turn REST APIs into MCP tools by annotating OpenAPI specs — the gateway serves operations as MCP tools on the /mcp path without a separate server. Any REST API, which is to say most APIs on the internet, can become an agent tool with configuration rather than code. [The platform under the agents](https://engineeringforward.substack.com/p/the-platform-under-the-agents) described how the platform underneath AI agents was being built — orchestration runtimes, isolation boundaries, evaluation loops. The REST-to-MCP conversion means the platform is also absorbing the integration layer. The tools that agents need are not being built one by one. They are being converted from existing infrastructure. One production caveat: tools/list is unauthenticated by default, and Google recommends securing discovery with JWT because API keys cannot protect that method. The opening is not without its gaps.

## The alumni and the insurance

Cherry Ventures hired Tatiana Shalalvand as a new partner with a specific mandate: back founders emerging from Lovable and Legora. The PayPal Mafia and the Stripe Mafia are Silicon Valley archetypes — the talent that flows out of category-defining companies becomes the seed of the next generation. Cherry's move is the first time a European VC has formalized this as an investment thesis for AI-native companies. Lovable and Legora are not just companies. They are training grounds where engineers learned to build with AI as the default, and the alumni carry that competence into new ventures.

The signal cuts deeper than talent flow. AI-native companies produce a different kind of engineer — one who thinks in agent loops, eval suites, and context management rather than monolithic application architecture. The Pragmatic Engineer's field notes from inside an AI-native company, described by Lenny Rachitsky as a first-person account of a millennial navigating a workplace where AI augmentation is the default, capture the cultural shift. The people leaving these companies carry a mental model that traditional companies are still trying to acquire. Cherry Ventures is betting that the mental model is worth more than the resume.

Humanos, a Lisbon-based startup, raised $3.2 million to build a network that continuously monitors and scores AI agents based on their behaviour. The category — agent insurance — did not exist six months ago. It exists now because agents are making decisions that carry liability: financial transactions, medical triage, customer communication. The insurance layer is a commercial response to the governance gap that [the reporting line](https://engineeringforward.substack.com/p/the-reporting-line) described. Agents get roles, scopes, and review gates. Insurance prices the risk of what happens when they fail. The market for agent governance is forming before the governance itself has matured.

## The governance gap underneath

The opening of the stack creates a governance problem that the closed-loop model did not have. When agents talk to each other across products, liability chains through two companies, two permission models, and a relay server that neither company controls. The Agent Tincan architecture, running on personal Tailscale networks, sidesteps this question by keeping the scale small. The pattern will not stay small.

Microsoft's Copilot integration into the org chart is one answer. Autopilot agents get their own permissions, their own box in the reporting structure, and their own evals. Satya Nadella's call for "evals specific to your company" rather than generic benchmarks is the governance version of local definition. The agent that reports to you gets measured by your standards, not by a public leaderboard. The 16,000 internal evals Microsoft runs are the performance review system for agents that are about to become staff members. Charles Lamanna's Autopilot "Apollo" has the same Outlook access as his executive assistant — a detail that makes the reporting line literal rather than metaphorical.

Linas's playbook for Claude Code Projects describes the governance from the practitioner's side. The firm model — coordinator as engagement lead, threads as workstreams, shared memory as institutional knowledge, review gates as quality checkpoints — produces the artifacts that governance requires: briefs, decision logs, review records. The people who set up projects this way get dramatically better results. The people who paste in a vague goal get merge conflicts and pull requests that do not fit together. The auto-resume trap, where threads hit plan limits and resume automatically when limits reset, potentially draining usage budgets overnight, is the unattended-staff-member problem. Governance is not optional. It is the difference between an agent that ships work and an agent that ships costs.

Anthropic's charm offensive across European capitals — the third Claude Founder House in London, with 250 founders told that companies like Legora and Wordsmith "thrive" alongside Anthropic's own vertical tools — is the frontier lab's response to the opening. The model alone is no longer enough to retain developers when a cheaper alternative appears. The Claude Founder House series is a direct investment in ecosystem relationships, the kind of moat that does not show up in benchmark scores but shows up in developer retention. Index Ventures partner Georgia Stevenson's observation that "moat" has vanished from the firm's investment committee memos confirms the pattern from the capital side. The things that used to protect companies no longer hold. What replaces them — talent, speed, ecosystem loyalty — is harder to manufacture.

## The physical constraint on openness

The opening of the stack runs into the same physical constraints that [what intelligence consumes](https://engineeringforward.substack.com/p/what-intelligence-consumes) traced. The CPU shortage is not abating. Cloud providers have killed spot pricing. Reservations need months of advance planning. Server orders take six months instead of two weeks. The root cause is AI agents running tools, compiling code, and executing tests — CPU-heavy workloads that shift the data center ratio from 1:8 to 1:1. Katelyn Lesse from Anthropic warned that teams who never planned CPU capacity must now forecast 12 months ahead. Julia 1's appeal — running on CPU, on a tablet — is partly a response to the hardware scarcity that the GPU-first AI industry created. When you cannot buy servers, you run on what you have.

The data lifecycle that ByteByteGo mapped from creation through deletion adds another constraint. Agents that generate and consume data autonomously create copies and derivatives that extend the lifecycle beyond traditional boundaries. GDPR's right to deletion becomes harder to honor when an agent has propagated information across five systems, each updating on a different schedule. The governance layer that companies like Humanos are beginning to price is the commercial recognition of this complexity. The more agents interoperate, the more data propagates, and the harder the lifecycle becomes to manage.

The training data frontier is also pushing outward. CO/AI reported that more than 50 tons of used books have been shipped from Japan to the United States, likely for AI training, following Anthropic's 2025 playbook of buying, scanning, and discarding under fair use. The reality TV archives at Warner Bros. Discovery — 300,000 hours of raw footage per year at a 100:1 shooting ratio — represent millions of hours of unscripted human behavior. Meta's glasses, with AI on by default and no training opt-out, point toward first-person capture as the next data source. The opening of the software stack is colliding with the closing of the data frontier. More interoperability means more agents, more agents means more compute, more compute means more physical resources, and the physical resources are finite.

## The opening's direction

The pattern across these stories is consistent. The decision layer is going open-source. Agents are learning to talk to each other across product boundaries. APIs are being absorbed into agent infrastructure. AI-native alumni are becoming a venture category. Agent insurance is forming around the governance gap. Each development, taken alone, is a product launch or a funding round. Taken together, they describe a stack that is opening — not because the companies at the top want it to, but because the economics of openness are beating the economics of closure.

Julia 1 on a Samsung tablet. Agent Tincan on a Tailscale network. REST APIs becoming MCP tools through annotation. DeepSeek's DSec paper exposing the sandbox infrastructure behind agent training at scale, with function-calling, container, microVM, and full-VM backends through one SDK. The infrastructure for interoperability is being built in garages and on personal servers, not in the labs that sell the models. The labs will adopt interoperability when the cost of not adopting it exceeds the cost of opening up. That calculation is already underway. The agents that cannot talk to each other are becoming the agents that cannot do the job.
