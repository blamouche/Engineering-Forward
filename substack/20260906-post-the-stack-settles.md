# The stack settles

*A protocol, a folder full of context, and a pricing table that values your data at $1.24 per million tokens — the AI stack is finding its permanent shape.*

ByteByteGo published a clarification last week titled "MCP vs RAG vs AI Agents." The newsletter laid out three concepts that the industry has spent two years conflating. MCP is a protocol — a standard interface for connecting models to external tools, the way HTTP connects clients to servers. RAG is a pattern — pulling fresh information into model context at query time, the way caching pulls data into a browser. AI agents are systems — autonomous programs that perform tasks and make decisions, the way applications use HTTP and caching to do things for users. The fact that this clarification was necessary tells you something about the maturity of the field. The stack is still being understood.

The same week, Every's Kieran Klaassen published a piece called "The Folder Is the Agent." After three months of failing to make agent swarms work — ten agents finishing simultaneously, ten results to evaluate without enough context to trust any of them — he discovered that the real agent architecture was already on his hard drive. A project folder with a CLAUDE.md file, accumulated documentation, and specialized skill definitions gives a model enough context to act as a specialist. Point Opus at one folder and it is a Rails engineer. Point it at another and it is an ops engineer who knows the incident history. The model does not change. The folder does. Klaassen now runs 44 such folder-as-agents across multiple projects with a file-based dispatch layer — a Ruby daemon that watches a directory for spawn requests, creates lead agents that decompose tasks, and spawns workers in the right folders.

## The protocol layer

MCP's role in the stack is becoming clear the way HTTP's role became clear in the 1990s. The protocol does not do anything itself. It defines how things talk. ByteByteGo's comparison was timely because the confusion between MCP, RAG, and agents was producing architectural decisions that mixed levels of abstraction. A team would build a "RAG agent" that was really an application using both a retrieval pattern and an agent framework, connected to tools through something that might or might not be MCP. The clarification matters because it separates concerns: MCP handles the connection, RAG handles the knowledge, the agent handles the action. Each layer can be improved independently.

The separation is already producing results. Anthropic's Claude Commerce Agents — released the same week — is a reference implementation that lives entirely on the merchant's side. Shopping agents handle customer-facing discovery. Merchant-operations agents handle staff workflows. The blueprint includes server-issued IDs, transaction caps, staged changes, and approval gates — safety controls in code, not in prompts. Nothing in the implementation places an order or charges a card. The narrow scope is the strategy. Anthropic is positioning itself as the intelligence layer that translates commercial intent into calls across catalog, inventory, pricing, and payment systems — leaving the transaction to Shopify, Visa, and Mastercard.

The contrast with OpenAI's approach is direct. ChatGPT's in-chat Instant Checkout was retired in March 2026, roughly five months after launch, after Walmart found conversion inside the chatbot ran about three times below its own site. ChatGPT now hands shoppers to retailer apps. Anthropic's thesis — that shoppers discover in AI but buy on the merchant's property — was validated by its competitor's failure. The lesson is architectural: the intelligence layer sits above the transaction layer, not inside it. Linas's Newsletter framed the launch by what Anthropic refused to build: no checkout protocol, no product catalog, no ad layer. The refusal is the positioning.

## The context layer

Klaassen's folder-as-agent discovery is the second clarification. The agent is not the model. The agent is the model plus enough context that you do not have to re-explain everything each time. The context lives in files — CLAUDE.md, architecture reports, runbooks, postmortems, skill definitions — that already exist in any well-maintained project. The agent is the folder.

This is a simpler architecture than the agent-swarm approach that preceded it, and it works better. The swarm failed because the bottleneck was never the agents' speed — it was the human manager's evaluation capacity. Ten agents finishing simultaneously produced ten results without enough context to know which to trust. The folder approach solves this by making the context the architecture. Each folder is a specialist because it contains the accumulated knowledge of a specific domain. The dispatch layer — a daemon watching a directory — is plumbing, not intelligence.

The discipline Klaassen describes is the part most teams will skip. "You can't vibe orchestrate," he writes. Before handing a flow to the dispatch layer, he builds the folder, establishes the flows, and uses them manually until they are predictable. Only when he trusts a flow does he hand it off. Skipping this step leads to agents opening duplicate pull requests and filing issues for work already done. The order is: build it, use it, trust it, then orchestrate it. [The companies building what they can't buy](https://engineeringforward.substack.com/p/the-companies-building-what-they-cant-buy) described how Ramp, Stripe, and Shopify rejected off-the-shelf agents to build their own — because their workflows exceeded what general-purpose tools could handle. The folder-as-agent pattern is the lighter version of the same insight. You do not need to build a custom agent platform. You need to build the context that makes a general model into a specialist.

Anthropic's own research supports the pattern. An Opus lead with Sonnet sub-agents outperformed a single Opus by 90 percent on research tasks. The cost: multi-agent systems burn 15 times more tokens. The tradeoff is explicit. You pay for the context that makes the agent effective, and you pay in tokens. Katie Parrott's Compound Writing plugin — which packages interviewing, outlining, drafting, and reviewing methods into installable AI skills — follows the same logic at the individual level. The process captures what the work teaches: a recurring aversion becomes a guardrail; a sentence-level preference becomes an agent instruction. The skill is the context. The folder is the agent. The principle is the same.

## The commodity layer

CO/AI's analysis of Meta's Muse Spark pricing makes the commodity layer explicit. Meta ships the model at two price points: $1.25 and $4.25 per million tokens for full privacy, or $0.10 and $0.20 if you let Meta train on everything you type. The $1.24 gap is not a discount. It is Meta telling you, to the penny, what your data is worth to an advertising company. At a billion tokens a day, that is $454,000 a year in foregone revenue Meta accepts to get your data.

Intelligence itself is commoditizing. When every lab has frontier-level models, nobody is selling intelligence — they are selling access to your workflow. Amazon ran this play with Amazon Basics on top of marketplace sellers. Apple sherlocked App Store apps. The labs are next. Outcome-based pricing and revenue share by vertical means the vendor learns your business well enough to eventually be the business. [The loop eats its own](https://engineeringforward.substack.com/p/the-loop-eats-its-own) described how 80 percent of frontier AI revenue comes from 1 percent of customers, and those customers are other AI companies. Meta's pricing reveals the other side of that loop: the vendor is not selling intelligence. It is buying your data with subsidized inference.

The response is to split your workflows. Commodity work — formatting, first drafts, ticket triage — can ride cheap or open models because there is nothing worth stealing. Judgment-dense work that exposes margins, customers, and process pays full freight for zero data retention or stays in-house with open weights. The split is not paranoid. It is the same logic that separates a company's public website from its internal databases. The difference is that the AI vendor sits inside both if you let it.

Every's camp on Fable 5.1 and GPT-6 Astra — both released within days of each other — illustrates the practical consequence. Over 200 people registered for a one-hour session on which model to use for which task. The demand exists because model selection has become a recurring operational decision, not a one-time choice. Katie Parrott's Vibe Check found that GPT-6 Astra excels at writing, consulting work, and visual design, while Anthropic's Fable 5.1 still outperforms on complicated app-building tasks. Astra has a habit of adding unneeded elements — a guided breathing exercise on a design that did not ask for one. Fable 5.1 has better instincts for product development. The practical recommendation is complementary, not competitive: use Astra for writing and visual prototypes, reach for Fable 5.1 for complicated products. CO/AI noted that GPT-6 Astra scored 61 on the independent intelligence index, dead even with the model it replaces. Its one real jump on ARC-AGI came from the harness — 99.9 percent with scaffolding versus 62.7 percent bare. The model did not get smarter. The scaffolding did.

## The tension between open and owned

The Mistral round — €3 billion led by Samsung with participation from Nvidia, ASML, and the EU Scaleup Fund — adds a different dimension to the stack. Samsung is a hardware company, not a venture firm. ASML is a semiconductor equipment monopoly. The EU Scaleup Fund is a political instrument. None of them are AI companies buying AI to build AI. They are industrial and political actors buying into the AI supply chain for strategic reasons.

The capital flows from hardware, not from token spending. That distinction matters. The US frontier loop is self-funding — AI companies buying AI to make more AI, the reflexive cycle [the loop eats its own](https://engineeringforward.substack.com/p/the-loop-eats-its-own) traced through Ramp's transaction data. The European model is externally funded — industrial capital and government funds buying into AI for sovereignty and supply chain positioning. Matt Clifford's move from the UK government's AI advisory role to Anthropic illustrates the political dimension of the same loop. Clifford shaped AI policy as an adviser to the prime minister. Now he joins one of the companies his policy work directly affected.

Legora, the Swedish legaltech, made the choice explicit. The company raised $550 million in March and decided not to build its own AI model. Training a frontier model "doesn't make business sense," the CTO explained at TechBBQ in Copenhagen. The rival Harvey did build one. The divergence is the stack finding its shape. Legora bets that the model layer is commodity infrastructure — something you rent, not something you own. Harvey bets the opposite. [Own the judgment, rent the rest](https://engineeringforward.substack.com/p/own-the-judgment-rent-the-rest) described this separation: own what is hard to replicate, rent what is becoming commodity. The model is becoming commodity. The judgment encoded around it is not.

## What the stack cannot clarify

The technical clarifications — protocol, pattern, system — are necessary but insufficient. MCP tells you how to connect. RAG tells you how to retrieve. The folder tells you how to organize context. None of them tell you whether the work is worth doing. ByteByteGo's newsletter also included a system design refresher: nine distributed systems patterns, virtualization versus containerization, and the step-by-step TLS handshake. ByteByteGo's companion piece on RAG systems reinforced the point: the embedding model — not the language model — is the most critical component, because no matter how powerful the LLM, it cannot generate correct answers from incorrectly retrieved context. A better language model cannot repair bad retrieval. The same principle applies to the stack. A better protocol cannot repair a bad decision about what to build.

Klaassen's "you can't vibe orchestrate" is the discipline the rest of the stack cannot enforce. The protocol can connect. The folder can contextualize. The pricing can expose the tradeoff. The decision to build it, use it, trust it, and only then orchestrate it — that is a judgment no protocol or pattern can encode. The stack is settling. The judgment is not.
