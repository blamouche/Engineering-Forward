# Read Less, Steer More
**Source**: https://blog.ezyang.com/2026/03/read-less-steer-more/
**Date**: March 18, 2026
**Author**: Edward Z. Yang
**Keywords**: AI coding, code review, prompting, workflow

## Elevator pitch
Edward Yang argues that with AI coding agents, developers should “read less, steer more” by directing outputs rather than inspecting every line.

## Takeaways
- AI agents increase the burden of code reading for juniors.
- Treat AI as a fast typist, not an autonomous teammate, when learning.
- Steering outputs reduces the cognitive load of review.
- Reading every edit at first builds intuition about model behavior.
- Creative work still requires human‑speed discovery and iteration.

## Synthesis
In “Read Less, Steer More,” Edward Z. Yang reflects on coaching junior developers using AI coding agents. He observes that AI‑generated code increases the demand for reading and reviewing, a skill already in short supply. His proposed solution is to shift from passively reading output to actively steering it: treat the model as a fast typist executing your intent rather than as a full autonomous teammate.

Yang argues that if you expect to understand code line‑by‑line, you should be deeply involved in its creation. The more you steer, the less cognitive burden you face when reviewing. This framing aligns with the idea of “vibe coding” as a trap for learners—if you hand off autonomy, you inherit the cost of understanding complex, unfamiliar code after the fact.

He recommends beginners spend time with “accept edits” disabled, forcing them to read and evaluate every change as it appears. This builds intuition about model behavior and helps them learn where the model tends to drift. Over time, as users gain confidence, they can re‑enable automation while still maintaining a mental model of the system’s behavior.

Yang also emphasizes that some aspects of creation are irreducibly human. Writing, testing, and deploying code surfaces insights that cannot be fully predicted in advance. For truly novel problems, slow iteration is unavoidable, and developers should not rush the discovery process just because the agent can type quickly.

Overall, the essay is a call for intentional workflow design. AI agents can accelerate output, but effective use requires active direction, not passive acceptance. The right mental model is not “AI teammate” but “AI executor,” especially for those still building their code‑reading skills.
