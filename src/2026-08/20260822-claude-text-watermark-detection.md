# How Claude's Text Watermark Works
**Source**: https://blog.bytebytego.com/p/ep223-ollama-vs-vllm-vs-sglang
**Date**: 2026-08-22
**Author**: ByteByteGo
**Keywords**: anthropic, claude, watermark, ai-text-detection, llm, text-generation, provenance

## Elevator pitch
Anthropic's text watermarking approach manipulates the next-token sampling process using a secret key and preceding words to restrict which candidate tokens are valid, creating a statistical signature that can be detected by checking match rates across the full text.

## Takeaways
- Watermarking works at the sampling step: instead of random sampling from probable next tokens, a keyed function uses a secret key plus previous few words to determine which candidates are valid
- The watermark signal is strongest where multiple plausible word choices exist — high-entropy positions carry the signal
- Detection works in reverse: for each word in a text, check if it's a valid choice based on the secret key and preceding words, then compute overall match rate as an AI-generated score
- Watermarked text matches the validity check far more often than non-watermarked text, creating a statistical fingerprint
- The approach is fragile at positions with few choices (function words, code) but robust in natural prose with many alternatives
- False negatives remain a challenge, especially for technical writing where vocabulary is constrained

## Synthesis
Anthropic's approach to watermarking AI-generated text is elegant in its simplicity: rather than adding visible markers or metadata, it subtly constrains the token sampling process itself. LLMs generate text word by word, producing probability distributions for the next token at each step. Normally, a random number generator samples from these distributions. With watermarking, a keyed function takes a secret key plus the previous few words and determines which candidate tokens are valid to pick from — narrowing the sampling space in a way that is invisible to the reader but statistically detectable.

The watermark signal is concentrated at high-entropy positions — places where multiple plausible word choices exist. At positions where the vocabulary is constrained (function words, code syntax, technical terminology), there are fewer choices and thus less room for the watermark to operate. This creates an inherent tension: the more natural and varied the prose, the stronger the watermark; the more technical and constrained the text, the weaker the signal.

Detection reverses the process. For any candidate word in a text, a checker verifies whether it would be a valid choice based on the secret key and the few preceding words. If the word is valid, it counts as a match. Running this across the entire text produces a match rate that serves as an AI-generation score. Watermarked text matches far more often than non-watermarked text because the watermarking process systematically selects valid tokens.

The practical implications are mixed. For provenance and authenticity verification, this is a meaningful step — it allows Anthropic to identify text generated by Claude without external tools. However, false negatives remain a significant problem, particularly for technical writing where constrained vocabulary limits the watermark's strength. The broader question of whether AI text detection creates more problems than it solves — false accusations, circumvention techniques, erosion of trust — remains unresolved.
