# An Engineering Team for the Cost of Codex
**Source**: https://every.to
**Date**: 2026-08-19
**Author**: Laura Entis / Every
**Keywords**: Codex, AI agents, harness engineering, Monologue, agent orchestration, AGENTS.md, solo developer, AI engineering team

## Elevator pitch
Naveen Naidu, the one-person shop behind Every's dictation app Monologue, now manages a "team of engineers" — except they're all custom Codex agents with their own AGENTS.md files, skills, memory, and codebases, representing a new paradigm where a solo founder orchestrates an AI engineering organization.

## Takeaways
- Naveen Naidu runs Monologue, Every's smart dictation app, as a solo developer but now operates as a "manager of engineers" — where the engineers are custom Codex agents.
- His agent roster includes dedicated engineer agents across different disciplines, a customer support agent, and a growth strategist, all maintaining the Monologue website and app.
- Each agent is a Codex project with a custom AGENTS.md file, skills, folders, memory, codebases, and context that turns it into a specialist.
- Agent-to-agent workflows are already operational: a customer support agent received a glowing review and handed it to the web engineer agent, which added the testimonial to the site autonomously.
- The future of harness engineering — building and maintaining the infrastructure around AI models — is trending toward doing less: the systems are becoming capable enough that the orchestration layer shrinks while the agent autonomy expands.

## Synthesis
The case of Naveen Naidu and Monologue represents a concrete, working example of what the "AI engineering team" thesis looks like in practice. Rather than hiring developers, Naidu has constructed a virtual engineering organization from Codex agents, each configured as a specialist with its own context, skills, and memory. This is not a theoretical exercise — the agents are maintaining a production application used by real customers.

The architecture is notable for its granularity. Each agent is a separate Codex project with a custom AGENTS.md file — the same pattern used by human engineering teams to define project conventions. The agents have dedicated codebases, memory of past work, and specialized skills that make them effective within their domain. The customer support agent handles user interactions, the web engineer agent manages the website, and a growth strategist agent works on user acquisition. This division of labor mirrors a traditional startup team structure, but executed entirely through AI.

The agent-to-agent workflow is the most significant development. When a customer sent a review that Naidu wanted to feature on the website, the customer support agent received the text and passed it to the web engineer agent, which then added the testimonial — all without human intervention in the execution step. This represents the beginning of autonomous agent orchestration, where agents communicate and delegate within a defined organizational structure.

The broader implication for harness engineering is that the field is moving toward less orchestration, not more. As models become more capable and agent frameworks mature, the scaffolding around them shrinks. The harness engineer's job is becoming one of configuration and delegation rather than prompt engineering and output validation. The paradox is that building a team of AI agents may ultimately require less engineering than building a single AI feature — because the agents handle their own complexity once properly configured.
