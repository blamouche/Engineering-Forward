# Google tests Jules V2 agent capable of taking bigger tasks

**Source**: https://www.testingcatalog.com/google-prepares-jules-v2-agent-capable-of-taking-bigger-tasks
**Date**: April 7, 2026
**Author**: TestingCatalog
**Keywords**: Google, Jules, Jitro, coding agents, goal-driven development, software engineering, AI tools

## Elevator pitch
Google appears to be rebuilding Jules around persistent goals and workspace-level insights, pointing toward coding agents that optimize for outcomes instead of one-off prompts.

## Takeaways
- Google seems to be developing a new Jules experience internally referenced as Jitro.
- The product direction shifts from prompt-by-prompt coding help toward goal-driven, persistent agent workspaces.
- Leaked tool references suggest support for goals, insights, tasks, and integrations across external tools.
- This would move the agent closer to an always-on collaborator than a narrow code assistant.
- Enterprise teams focused on measurable improvements may find this model more compelling than classic autocomplete or task bots.

## Synthesis
The most interesting thing about this Jules V2 report is the implied change in abstraction. Most coding agents today still operate at the task level: the user tells the system what to change, the system tries to execute. A goal-oriented agent flips that model. Instead of asking for a pull request, you define an outcome—improve latency, increase test coverage, reduce accessibility issues—and let the system decompose the work. That is a much more ambitious, and potentially much more useful, interface for software engineering.

The leaked tool list matters because it suggests Google is building supporting infrastructure around that abstraction: goals, insights, task histories, and integrations. That sounds less like a chatbot and more like a workspace for agent management. If that holds, the competitive frame shifts. Google would not just be shipping another coding agent. It would be shipping a managerial layer for multiple ongoing software objectives.

That said, the promise is bigger than the trust model. Goal-seeking agents are inherently more dangerous than task-following ones because they have more room to make surprising decisions. Enterprise buyers may like the narrative of KPI-driven development, but they will only adopt it if the system is legible, reviewable, and easy to constrain.

Still, the direction feels important. The next wave of coding tools probably will not be won by whoever autocompletes code fastest. It will be won by whoever turns agents into reliable systems for pushing product and engineering outcomes forward over time.
