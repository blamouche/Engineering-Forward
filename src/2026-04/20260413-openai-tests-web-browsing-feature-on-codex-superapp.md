# OpenAI tests web browsing feature on Codex Superapp

**Source**: https://www.testingcatalog.com/openai-tests-web-browsing-feature-on-codex-superapp
**Date**: April 13, 2026
**Author**: TestingCatalog
**Keywords**: OpenAI, Codex, web browsing, superapp, PR workflows, agent workspaces

## Elevator pitch
TestingCatalog says OpenAI is broadening Codex from a coding agent into a wider work surface, with browser capabilities, task lists, PR management, preview comments, and onboarding flows tailored separately for casual and professional users.

## Takeaways
- The leaked UI points to Codex becoming a unified environment for planning, building, previewing, and shipping rather than a narrow code-generation tool.
- Built-in browsing and non-developer onboarding support the idea that Codex is being positioned as a broader OpenAI superapp substrate.
- PR review and preview-comment workflows suggest OpenAI is trying to own the full software loop, not just code drafting.

## Synthesis
The interesting part of this report is not that OpenAI may add yet another feature to Codex. It is that the product is apparently being stretched into a general-purpose execution surface with coding as its anchor tenant. Browsing, task orchestration, preview comments, and PR management all point in the same direction: Codex is becoming a workspace where intent, execution, and review live together.

That matters strategically because standalone chat is increasingly a weak moat. The stronger position is to own the loop around work: plan the task, browse for context, generate artifacts, preview outcomes, collect comments, and ship. If Codex can absorb those steps, it becomes harder to dislodge because the value is no longer just the model response. It is the whole operating environment wrapped around it.

The dual onboarding path—basic versus professional—is also telling. OpenAI seems to want one surface that can serve both mainstream assistant use and heavier developer workflows without splitting the brand or fragmenting product investment. That is basically the superapp play in miniature: unify the context, then widen the job-to-be-done over time.
