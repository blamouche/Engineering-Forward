# OpenAI develops platform for always-on Agents on ChatGPT
**Source**: https://www.testingcatalog.com/openai-develops-platform-for-always-on-agents-on-chatgpt/
**Date**: April 21, 2026
**Author**: Unknown
**Keywords**: OpenAI, ChatGPT, agents, workflows, persistent automation

## Elevator pitch
OpenAI appears to be turning ChatGPT from a single assistant into a host platform for persistent role-based agents that can run continuously and communicate outside the chat window.

## Takeaways
- TestingCatalog reports that OpenAI is building a beta agent surface inside ChatGPT under the codename Hermes.
- The product direction points to always-on agents rather than one-shot task execution.
- Workflows, skills, connectors, scheduling, and messaging integrations appear to be part of the same stack.
- Placeholder roles like CTO and CPO suggest OpenAI is thinking in terms of multi-agent teams.
- If shipped broadly, ChatGPT could become a consumer-scale operating layer for persistent automation.

## Synthesis
The reported Hermes work inside ChatGPT is interesting because it suggests OpenAI is pursuing a much more ambitious interpretation of “agents” than the simple task runner model that has dominated many recent launches. According to TestingCatalog, Hermes is being developed as a top-level destination inside the Agents area of ChatGPT, with support for configurable, always-on agents that act more like teammates than temporary assistants.

Several details matter here. The reported feature set includes custom workflows, attachable skills, connectors, messaging integrations, and task scheduling. Taken together, that reads less like a single UI enhancement and more like a platform architecture. Instead of asking ChatGPT to do something once, users would be able to define specialized agents, give them tools and triggers, and let them operate continuously across contexts.

That would represent a meaningful shift in what ChatGPT is. Historically, the product has centered on one assistant interface that becomes more useful when the user returns and asks for more work. A persistent agent layer changes that model. It creates the possibility of delegated, ongoing activity, where agents monitor events, respond to messages, trigger workflows, and maintain role-specific behavior over time.

The placeholder roles mentioned in the report, such as CTO or CPO, reinforce that interpretation. OpenAI may be imagining a user account not as one conversation with one model, but as a small portfolio of specialized agents. That starts to resemble an AI organization chart rather than a chat product. It also aligns with the broader trajectory of agent products across the industry, where the real product ambition is coordination, persistence, and background work rather than just improved dialogue.

The competitive angle is obvious too. TestingCatalog notes that Notion has already moved into shared, trigger-based custom agents. If OpenAI can bring a similar concept directly into ChatGPT, it would be entering the category with far larger distribution and an existing base of users already familiar with skills, connectors, and scheduled tasks. That gives OpenAI an unusual advantage: it can turn a mass-market assistant into an agent host without asking users to adopt a new product from scratch.

None of this is confirmed as a shipped roadmap, and leak-based reporting always deserves caution. But if the feature lands close to the reported shape, it would mark a real platform transition. ChatGPT would stop being merely a place to ask for help and start becoming an environment where a set of agents works in parallel on the user’s behalf.
