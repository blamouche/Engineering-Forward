# This week on How I AI: I gave Claude Code our entire codebase. Our customers noticed.

**Source**: https://www.lennysnewsletter.com/p/this-week-on-how-i-ai-i-gave-claude
**Date**: April 6, 2026
**Author**: Lenny Rachitsky
**Keywords**: customer support, Claude Code, codebase search, Confluence, Slack, support operations, Galileo

## Elevator pitch
Lenny highlights a strong support workflow from Galileo: use Claude Code across 15 repos plus Confluence and customer-specific notes so field engineers can answer deep technical questions without constantly interrupting engineering.

## Takeaways
- Galileo’s field engineer uses Claude Code across 15 repos as the real source of truth for customer answers.
- A simple daily sync script keeps the local multi-repo workspace fresh.
- Customer-specific “quirks” pages let the AI tailor deployment guidance instead of producing generic answers.
- Support conversations can be turned into reusable knowledge base articles.
- AI changes customer-facing technical roles by making code comprehension a service advantage.

## Synthesis
This newsletter item is interesting because it reframes AI-assisted coding tools as customer-experience infrastructure. The Galileo workflow is not about shipping product faster; it is about helping a field engineer answer deep, implementation-level customer questions by querying code, Confluence, and customer-specific notes together. That is a powerful pattern for any technical support or solutions team stuck between stale docs and overloaded engineers.

The clever part is treating the codebase as the primary truth source and layering context on top. Official documentation remains useful, but it is no longer the ceiling of what support can know. By keeping a synchronized multi-repo workspace and adding customer quirks, Claude Code can produce responses that are both technically grounded and deployment-specific.

There is also an org-design lesson here. AI creates leverage not only for builders but for adjacent roles that traditionally depend on engineering for answers. Field engineers, support staff, and solution architects become more autonomous when they can interrogate implementation directly. That reduces interruptions and improves response quality at the same time.

The broader implication is that customer experience may become an underrated AI battleground. Plenty of teams will use AI to move faster internally. Fewer will use it to make customer interactions more precise, contextual, and high-trust. That is a harder edge to copy.
