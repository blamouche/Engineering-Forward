# Stop Coding and Start Planning

**Source**: https://every.to/source-code/stop-coding-and-start-planning-be0b4fd1-5898-4b09-bfda-0b00ea0004fd

**Date**: January 28, 2026

**Author**: Kieran Klaassen

**Keywords**: AI, planning, vibe coding, agents, productivity, software development, institutional knowledge

## Elevator pitch

AI-assisted development works best when engineers invest time in strategic planning rather than immediate coding, as planning teaches AI systems architectural preferences that compound over time while pure coding only solves isolated problems.

## Takeaways

- Vibe coding without planning makes engineers sloppy by skipping the strategic thinking that yields highest returns
- Planning teaches AI systems how developers think and creates lasting institutional knowledge, while coding only solves individual problems
- Work falls into three fidelity levels: quick fixes needing minimal planning, multi-file features where planning yields massive ROI, and large uncertain features requiring prototyping first
- One hour of deliberate planning before implementing a complex feature can eliminate days of debugging and achieve pixel-perfect results
- Better AI models improve automatically, but institutional knowledge about preferences and patterns compounds through deliberate review processes

## Synthesis

Kieran Klaassen, General Manager of Cora, presents a counterintuitive argument for AI-assisted software development: the most productive engineers should spend more time planning and less time coding. His core observation is that AI tools have made it possible to skip planning entirely, prompting developers to jump straight into implementation. This capability has paradoxically made engineering work sloppier.

The distinction Klaassen draws between planning and execution centers on institutional knowledge. When developers engage in vibe coding, they prompt with requests like "Add email validation to the signup form." This solves the immediate problem but teaches the AI system nothing about architectural preferences or design patterns. In contrast, planning with AI involves researching approaches, evaluating tradeoffs, and documenting decisions. This knowledge persists and informs future work.

Klaassen introduces a framework of three work fidelities to guide when planning delivers returns. Fidelity One covers obvious bugs and one-line changes where planning overhead exceeds implementation time. Fidelity Two represents the productive middle ground: features that span multiple files where planning yields massive returns on investment. At this fidelity level, the AI system learns fastest because it observes thoughtful decision-making rather than reactive fixes. Fidelity Three encompasses major features with significant uncertainty, requiring rapid prototyping to clarify requirements before rigorous planning begins.

A concrete example illustrates the methodology. Klaassen spent one hour planning the implementation of Figma designs into Cora's email bankruptcy feature. This planning session documented the approach, identified edge cases, and established patterns. He then created agents to execute the plan. The result was pixel-perfect implementation across multiple screens without weekend debugging sessions. The hour invested in planning eliminated what would have been days of iterative fixes.

The compounding nature of planning distinguishes it from pure coding output. AI models improve automatically through vendor updates, delivering performance gains without developer effort. However, institutional knowledge about specific preferences, architectural patterns, and domain constraints only accumulates through deliberate documentation and review processes. This knowledge makes future work exponentially more productive because the AI system understands not just what to build but how the organization thinks about building. For engineering teams adopting AI tools, the implication is clear: the competitive advantage lies not in coding speed but in the quality of planning and preference documentation that shapes AI-assisted work.
