## Elevator pitch
ByteByteGo's weekly system design refresher covers the full spectrum of API concepts engineers should master — from HTTP methods through REST/GraphQL/gRPC tradeoffs to security and reliability patterns — alongside a practical five-layer prompt injection defense guide, a curated list of 12 AI papers that shaped the field, and architecture comparisons across monolithic, microservices, and serverless models.

## Takeaways
- **API design fundamentals still matter**: Most API problems begin with basic HTTP details (methods, status codes, request formats) and compound through design decisions around naming, pagination, versioning, and backward compatibility that get insufficient attention early in the design process.
- **Protocol choice is contextual**: REST, GraphQL, gRPC, webhooks, and WebSockets each make sense in different situations — the challenge is knowing which fits the system and use case, not which is "best" in the abstract.
- **Five-layer prompt injection defense**: No single defense suffices. Model-level defenses include spotlighting (wrapping untrusted text in control tags) and instruction hierarchy (fine-tuning to rank developer > user > third-party). System-level defenses include least-privilege tools, human-in-the-loop approval, and a planner/executor split where the planner has tools but never sees untrusted content, while the executor reads untrusted content but has no tools.
- **12 AI papers that shaped everything**: AlexNet (2012), GANs (2014), Transformer (2017), GPT-3 (2020), InstructGPT (2022), Scaling Laws (2020), ViT (2020), Latent Diffusion (2021), DDPM (2020), CLIP (2021), Chain-of-Thought (2022), and RAG (2020) — each marked a paradigm shift rather than an incremental improvement.
- **Monolith vs microservices vs serverless**: Most production systems use a monolith at the core with services spun up where independent scaling or faster deploys are needed, and serverless appearing later for notifications or background jobs — not a binary choice.
- **Seven load balancer use cases**: Traffic distribution, SSL termination, session persistence, high availability, horizontal scaling, DDoS mitigation, and health monitoring — each addresses a distinct production concern.

## Synthesis
ByteByteGo's weekly refresher is designed for working engineers who need to keep a broad systems vocabulary current. The issue works because it doesn't try to be exhaustive on any single topic; instead, it provides the mental scaffolding — the key concepts, the decision points, and the tradeoffs — that an engineer needs to navigate each area.

The API design section is a reminder that most API problems are not exotic. They begin with HTTP fundamentals (methods, status codes, request formats) and compound through design decisions that seem small at first: naming conventions, pagination strategies, versioning approaches, error response structures, and backward compatibility commitments. The protocol choice — REST, GraphQL, gRPC, webhooks, WebSockets — gets the most attention in technical debates, but ByteByteGo correctly frames it as contextual rather than ideological. Each protocol makes sense in specific situations, and the challenge is matching the protocol to the system's access patterns, performance requirements, and consumer expectations. Security (API keys, OAuth, JWTs, scopes, permissions) and reliability (timeouts, retries, idempotency, rate limits, caching) are the areas where weak decisions cause real production problems, and they're the areas most likely to be deferred until a system is under pressure.

The prompt injection defense guide is particularly timely given that prompt injection tops the OWASP LLM Top 10 and there is no single fix. The two-family framework — model-level and system-level — is the right mental model. Spotlighting (wrapping untrusted text in `<UNTRUSTED>...</UNTRUSTED>` tags) and instruction hierarchy fine-tuning address the model's tendency to confuse data with instructions. Least-privilege tools, human-in-the-loop approval, and the planner/executor split address the system's tendency to amplify a compromised model's reach. The planner/executor split is the most architecturally interesting: by ensuring the LLM with tool access never sees untrusted content and the LLM that reads untrusted content has no tools, you create a separation that makes indirect injection much harder to exploit — even if neither model is perfectly resistant to injection on its own. Production systems like Gmail stack these defenses, and the stacking is what makes indirect injection manageable rather than solved.

The 12 AI papers list is a curated timeline of paradigm shifts. AlexNet (2012) proved deep neural networks could see, igniting the deep learning era. The Transformer (2017) introduced the architecture behind everything. GPT-3 (2020) showed that scale unlocks emergent abilities. InstructGPT (2022) turned raw LLMs into useful assistants through RLHF. Chain-of-Thought (2022) unlocked complex reasoning through a prompt pattern. RAG (2020) grounded LLMs in facts by retrieving real documents. Each paper didn't just improve performance; it changed how researchers thought about the problem. The list is necessarily incomplete — it omits reinforcement learning foundations, multimodal alignment beyond CLIP, and efficiency innovations like Flash Attention — but it captures the papers that most directly shaped the current landscape.

The monolith vs. microservices vs. serverless comparison is the most practically useful section. ByteByteGo's framing — "most production systems don't use just one approach" — matches what experienced engineers actually see. The pattern is a monolith at the core, services spun up where independent scaling matters, and serverless for event-driven workloads like notifications or background jobs. This is more useful than the ideological debates that frame it as a binary choice, and it reflects the reality that architecture decisions are reversible but expensive to reverse.
