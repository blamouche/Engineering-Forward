# How Top PMs Increase Their Leverage with AI

**Source**: https://www.lennysnewsletter.com/p/how-top-pms-increase-their-leverage
**Date**: 2026-06-30
**Author**: Colin Matthews (guest post, Lenny's Newsletter)
**Keywords**: PM, AI leverage, AI-native builder, prototyping, MCP, Claude Code, Codex, product management, framework

## Elevator pitch

A three-ladder framework from AI instructor Colin Matthews — personal, product, and systems leverage — that maps how the most AI-native PMs are operating in mid-2026, from using AI to write text to shipping production code via pull requests.

## Takeaways

- The framework consists of three "ladders of leverage": personal leverage (your own to-do list), product leverage (shipping the right things faster), and systems leverage (repeatable AI workflows)
- Personal leverage ladder: Rung 1 = AI writes text (PRDs, emails), Rung 2 = AI creates artifacts (slides, models), Rung 3 = AI completes full to-do items via MCP-connected tools (PostHog, Amplitude, Notion)
- Product leverage ladder: Rung 1 = web-based prototypes (Lovable, Replit), Rung 2 = code-based prototypes using real codebase (Claude Code, Codex), Rung 3 = agent ships production PRs
- MCP (Model Context Protocol) is the key enabler — connecting LLMs to tools like PostHog, Figma, Amplitude via Claude, ChatGPT, or Gemini connectors
- The PM role is shifting from coordinating people to prototyping with real code, querying data conversationally, and running coding AI agents

## Synthesis

Colin Matthews, who has trained over 30,000 PMs on AI integration, observes a shift in 2026: executives now expect employees to use AI to complete entire tasks, not just prototype. His framework maps three ladders of leverage, each with three rungs representing an order-of-magnitude increase in AI-assisted output.

The personal leverage ladder is the most common starting point. At Rung 1, PMs use AI to help write PRDs and emails, then copy-paste. At Rung 2, AI generates actual artifacts — financial models, slides, small prototypes. At Rung 3, connected via MCP to tools like PostHog, a PM can ask AI to run a full retention analysis and produce an HTML visualization with cited sources, completing a task that previously would have filled the gap between meetings. Matthews recommends asking the LLM to "cite your sources" so outputs can be validated, and locking in successful workflows as reusable skills.

The product leverage ladder closes the gap between what PMs want to build and what they can ship. Rung 1 uses web-based tools (Lovable, Replit, Magic Patterns) for quick concept prototypes — useful for validation but disconnected from real code. Rung 2 uses Claude Code or Codex with a stripped-down version of the real codebase — a UI-only repo with mock data that a PM can run without backend dependencies. Rung 3 has agents ship production PRs for copy changes, small UI tweaks, or views using existing backend code. Matthews is clear that PMs shouldn't try to be worse engineers than their team — knowing when to write a doc, ship a prototype, or create a PR is as important as the technical ability itself.

The systems leverage ladder, behind the paywall, addresses repeatable workflows for consistently outsourcing work to AI. The article also announces a course, "Become an AI-Native Builder," co-developed with Lenny, teaching PMs to use Codex, Claude Code, Cursor, and MCP tools in day-to-day work — a signal that the PM-as-coordinator role is giving way to the PM-as-AI-native-builder.
