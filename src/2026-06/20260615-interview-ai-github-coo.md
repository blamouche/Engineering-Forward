# I Interviewed an AI Version of GitHub's COO—Then Spoke to the Real One
**Source**: https://every.to/emails/click/09c24c7a4dd0698c6700616530f966228bcd55b2042584e4395d015976ea692d/eyJzdW
**Date**: 2026-06-15
**Author**: Mike Taylor (Every)
**Keywords**: AI personas, simulated interviews, GitHub, Kyle Daigle, Copilot, agentic code review, agentic merge, developer demographics, open source maintainers

## Elevator pitch
Every's Mike Taylor built an AI persona of GitHub COO Kyle Daigle from public writing and interviews, asked it the same questions as the real interview, and discovered that the simulation's gaps—where it had no public data—were the most valuable prep tool for identifying what to ask live.

## Takeaways
- Out of 12 questions, the AI persona gave 2 strong matches, 4 partial matches, and 6 material misses—when it lacked evidence, it said so instead of inventing, which revealed where the public record was thin
- GitHub is on track for 14 billion commits in 2026 (vs. 1 billion for all of 2025), with 17 million pull requests created by agents alone in March 2026
- GitHub shipped agentic code review (finds novel vulnerabilities, agent implements changes) and agentic merge (Copilot merges PRs, waits for CI, enforces policies)
- GitHub's expansive view of "developer" now includes legal and finance teams using Copilot—non-developers are building apps and assets alongside traditional developers
- AI personas can replicate human responses with ~85% accuracy in some studies, making them useful for high-stakes prep (getting out of your own head, building confidence) even though they're no substitute for real interviews

## Synthesis
Mike Taylor's experiment is a clever piece of practical AI journalism that doubles as a playbook for using AI personas as interview preparation tools. The core insight is counterintuitive: the AI simulation's misses were more valuable than its hits. When the persona couldn't produce the art-school story or the legal-and-finance-teams example, those gaps showed the journalist exactly where the public record was thin and where to invest interview time. The simulation's hits, on the other hand, confirmed what was already known—less useful for a journalist trying to generate new information.

The GitHub data revealed in the interview is significant for engineering teams. The platform is seeing explosive agent-driven activity: 14 billion commits projected for 2026 versus 1 billion for all of 2025, with 17 million agent-created pull requests in March alone. GitHub's COO Kyle Daigle pushed back on the "slop" narrative, arguing that the industry is climbing past super-early adoption and learning what's possible when developers work alongside multiple agents using their skills, resources, and context.

The product announcements are directly relevant to engineering workflows. Agentic code review now finds novel vulnerabilities and can implement changes based on review comments. Agentic merge lets developers define what Copilot is allowed to do and have it handle the mechanical steps of finalizing a PR—waiting for CI, enforcing policies. For open source maintainers drowning in pull requests, GitHub is building contributor acceptance controls that let communities define who they accept changes from and how much work contributors need to demonstrate.

The broader lesson for the engineering community is about AI persona utility. Taylor's startup Ask Rally found that AI personas can replicate real human responses with ~85% accuracy in some studies. The practical application isn't replacing real conversations—it's using simulations to identify blind spots, build confidence in strategy, and avoid costly mistakes in high-stakes scenarios. The simulation correctly predicted GitHub's thesis about expanding who gets to build software but couldn't name products that hadn't been publicized, making it a complement to—not a replacement for—real journalism and real interviews.
