# Project Glasswing: what Mythos showed us
**Source**: https://blog.cloudflare.com/cyber-frontier-models/
**Date**: 2026-05-18
**Author**: Grant Bourzikas
**Keywords**: Mythos Preview, Anthropic, Project Glasswing, vulnerability research, LLM, exploit chain, proof-of-concept, multi-agent harness, signal-to-noise, AI security, Cloudflare, offensive security, cyber frontier models

## Elevator pitch
Cloudflare's hands-on evaluation of Anthropic's Mythos Preview cyber frontier model demonstrates a generational leap in AI-driven vulnerability discovery — one that can chain low-severity bugs into working exploits and generate its own proofs, but only when embedded in a purpose-built multi-agent harness rather than used as a standalone tool.

## Takeaways
- Mythos Preview can autonomously chain multiple low-severity bugs into a single working exploit and generate its own proof-of-concept code, closing the gap between "finding a bug" and "proving it's exploitable" — capabilities previous frontier models consistently failed at.
- The model's emergent safety guardrails are inconsistent: semantically equivalent tasks can produce opposite outcomes depending on framing, meaning organic refusals alone are insufficient as a safety boundary and additional safeguards are required for general availability.
- Signal-to-noise remains a critical challenge: LLMs have an inherent bias to "find" bugs even when none exist, and memory-unsafe languages like C/C++ produce far more false positives than memory-safe languages — but Mythos Preview's PoC-first approach significantly reduces time spent on triage.
- Pointing a generic coding agent at a repository fundamentally doesn't work for vulnerability research — the narrow, parallel nature of real security research demands a multi-agent harness with scoped tasks, adversarial validation, and dedicated trace/reachability stages.
- Cloudflare's eight-stage harness (Recon → Hunt → Validate → Gapfill → Dedupe → Trace → Feedback → Report) running ~50 concurrent hunters achieved high-coverage results across critical infrastructure, and the architecture lesson is that defenders must shift from "patch faster" to "make exploitation harder" through defense-in-depth design.

## Synthesis

Cloudflare's blog post, authored by CSO Grant Bourzikas, delivers a candid field report from Project Glasswing — Anthropic's controlled research program granting early access to Mythos Preview, a dedicated cyber frontier model. Cloudflare pointed the model at over fifty of their own repositories spanning their runtime, edge data path, protocol stack, control plane, and open-source dependencies. The post is less a benchmark and more an operational after-action review: what worked, what broke, and what the industry should learn before these capabilities become broadly available.

The headline finding is that Mythos Preview represents a qualitative shift, not an incremental one. Two capabilities distinguish it: exploit chain construction and autonomous proof generation. Previous frontier models could identify individual bugs and write thoughtful analyses about them, but they stopped there. Mythos Preview takes multiple low-severity primitives — a use-after-free here, an information leak there — and reasons through how to combine them into a complete exploit chain, then writes, compiles, and iterates on proof-of-concept code in a scratch environment until it works. The reasoning Cloudflare observed "looks like the work of a senior researcher rather than the output of an automated scanner." This closes the critical gap between suspected vulnerability and demonstrated exploitability.

However, the post is refreshingly honest about the model's limitations. Despite operating without the additional safety layers present in publicly available models, Mythos Preview exhibited emergent refusal behaviors — but inconsistently. Cloudflare documented cases where the model refused vulnerability research on a project, then accepted the identical task after an unrelated environment change. In another instance, it confirmed serious memory bugs but refused to write a demonstration exploit, only to comply when the request was rephrased. Bourzikas draws a clear conclusion: organic guardrails are real but not reliable enough to serve as a standalone safety boundary. Any general release of such a model must layer additional safeguards on top.

The post dedicates considerable space to the signal-to-noise problem, an issue that predates AI but is amplified by it. Two factors dominate: programming language choice (C/C++ codebases produce dramatically more false positives than memory-safe languages) and model bias (LLMs will "find" bugs whether they exist or not, hedging with "possibly" and "potentially"). Mythos Preview improves the situation because findings that arrive with a working PoC are actionable rather than speculative, but the broader lesson is that any vulnerability scanning pipeline must include dedicated validation stages — you cannot rely on a single model checking its own work.

Perhaps the most operationally valuable section is Cloudflare's blunt assessment that "pointing a generic coding agent at a repo doesn't work." Coding agents are designed for single-stream, feature-building workflows; vulnerability research is narrow, parallel, and requires thousands of independent hypotheses across a codebase. A single agent session against a 100,000-line repository covers perhaps 0.1% of the attack surface before context window compaction discards earlier findings. The solution Cloudflare arrived at is an eight-stage harness: Recon (architecture document generation and task queue creation), Hunt (~50 concurrent agents running scoped vulnerability class tasks with compilation and PoC capabilities), Validate (an independent adversarial agent that tries to disprove findings), Gapfill (re-queuing areas that were touched but not thoroughly covered), Dedupe (collapsing findings sharing root causes), Trace (cross-repository reachability analysis using a symbol index — described as "the stage that matters most"), Feedback (converting reachable traces into new hunt tasks in consumer repositories), and Report (structured, schema-validated output to an ingest API).

The strategic conclusion extends beyond tooling. Bourzikas warns that many security teams are responding to the acceleration of AI-powered attacks by chasing ever-faster patch SLAs — some now targeting two hours from CVE release to deployment. He argues this is misguided: if regression testing takes a day, a two-hour SLA means skipping it, and the resulting bugs tend to be worse than the original vulnerability. The real answer is architectural: design systems so that exploitation is hard even when a bug exists, through defense-in-depth, blast-radius containment, and the ability to deploy mitigations universally rather than per-team. The post closes by acknowledging the dual-use nature of these capabilities and positioning Cloudflare's platform as the architectural answer for its customers, with more to come in subsequent weeks.

This is a rare artifact: a security vendor honestly documenting not just what an advanced AI model can do, but the scaffolding required to make it useful at production scale. The implicit thesis is that the harness matters as much as the model — and that the real competitive advantage in AI-assisted security will belong to organizations that build the best orchestration layer, not those with the best model access.
