# AI Tooling for Software Engineers in 2026
**Source**: https://newsletter.pragmaticengineer.com/p/ai-tooling-2026
**Date**: March 3, 2026
**Author**: Gergely Orosz and Elin Nilsson
**Keywords**: AI tools, Claude Code, GitHub Copilot, Cursor, Codex, survey, developer productivity, agentic coding

## Elevator pitch
A survey of 900+ software engineers reveals Claude Code has rocketed to #1 in just eight months, AI usage is fully mainstream at 95% weekly adoption, and 55% now regularly use AI agents with staff+ engineers leading the charge.

## Takeaways
- Claude Code went from zero to #1 AI coding tool in eight months, surpassing GitHub Copilot and Cursor
- 95% of respondents use AI tools at least weekly; 75% use AI for at least half their engineering work; 56% do 70%+ of work with AI
- 55% now regularly use AI agents — up from near-zero 18 months ago — with staff+ engineers as the heaviest users (63.5%)
- Company size drives tool choice: tiny startups overwhelmingly use Claude Code (75%), while large enterprises default to GitHub Copilot (56%) due to procurement
- Agent users are nearly twice as likely to be excited about AI; non-users are twice as likely to be skeptical

## Synthesis
The Pragmatic Engineer's 2026 AI tooling survey, conducted between January and February 2026 with over 900 respondents, provides the most comprehensive snapshot yet of how software engineers are actually using AI in their daily work. The headline finding is unmistakable: Claude Code, released in May 2025, has become the most-used AI coding tool in just eight months, overtaking both GitHub Copilot and Cursor. This velocity is unprecedented in developer tooling and signals a market that is still in rapid flux.

Anthropic's dominance extends beyond Claude Code. Opus and Sonnet models are mentioned more often than all other models combined for coding tasks, establishing Anthropic as the go-to model provider for software engineering. This is complemented by a tight three-way race among standalone chatbots (ChatGPT, Gemini, Claude) for non-coding AI tasks, suggesting no clear winner has emerged for general-purpose AI assistance among engineers.

The survey confirms that AI is now fully mainstream in software engineering. The question has shifted from "whether" to use AI to "which tools" to use. Only 2.1% of respondents do not use AI tools at all, and three-quarters use AI for at least half their engineering work. This is not edge-case adoption — it is the new baseline of professional practice. The data aligns with anecdotal evidence that AI-assisted development has become the default mode of working for most engineers.

The rise of AI agents is perhaps the most significant trend. Eighteen months ago, agent usage was nearly nonexistent — limited to a handful of experimenters. Today, 55% of respondents regularly use AI agents for tasks including code review, bug investigation, debugging, automated chores, and "crafting" code. The most common setup is a split-screen arrangement: Claude Code running in a terminal to drive work, with an IDE open for reviewing changes. This pattern suggests engineers are not ceding control to agents but are developing new collaboration patterns where they direct and review agent output.

A sharp divide exists by company size. In the tiniest companies, 75% use Claude Code and 42% use Cursor — individual engineers choose their tools. In enterprises of 10,000+ employees, 56% use GitHub Copilot — procurement policies and Microsoft's enterprise sales motion, not individual preference, determine tool adoption. This bifurcation has implications for how AI tooling companies design their go-to-market strategies: bottom-up adoption works for startups and small teams, while enterprise contracts remain the gatekeeper for large organizations. The correlation between agent usage and AI enthusiasm also suggests a feedback loop: the more engineers use sophisticated AI tools, the more positive they become, creating a self-reinforcing adoption cycle.
