# Gas City
**Source**: https://github.com/gastownhall/gascity
**Date**: May 19, 2026
**Author**: Gas Town Hall (Chris Sells, Julian Knutsen)
**Keywords**: Gas City, multi-agent orchestration, software factory, AI coding agents, Claude Code, Kubernetes for agents

## Elevator pitch
Gas City is the successor to Steve Yegge's Gas Town — an open-source orchestration-builder SDK that extracts reusable multi-agent infrastructure into a configurable toolkit with declarative city configuration, multiple runtime providers, and Beads-backed work tracking.

## Takeaways
- Gas City is an orchestration-builder SDK, not a monolithic tool: it provides composable infrastructure (runtime providers, work routing, health patrol) configured via city.toml.
- Multiple runtime providers are supported: tmux, subprocess, exec, ACP, and Kubernetes — making it adaptable to different environments.
- Built on Beads (a git-backed data plane) for work tracking, with formulas, molecules, waits, and mail for inter-agent communication.
- A controller/supervisor loop reconciles desired state to running state, similar to Kubernetes architecture.
- Has seen significant community adoption: 258 issues, 225 pull requests on GitHub.
- Requires tmux, git, jq, and various CLI tools — with a quick brew install path for macOS users.

## Synthesis
Gas City is the community-driven successor to Steve Yegge's Gas Town, rebuilt as an orchestration-builder SDK by Chris Sells (former Flutter lead at Google, grew it to 3 million developers) and Julian Knutsen (former Block technical lead). Where Gas Town was an opinionated monolith, Gas City extracts the reusable infrastructure into a configurable, composable toolkit.

The project is organized around a declarative city.toml configuration and supports multiple runtime providers — tmux, subprocess, exec, ACP, and Kubernetes — making it adaptable from local development to cloud deployment. It uses Beads, Yegge's universal git-backed data plane, for work tracking with concepts like formulas, molecules, waits, and mail for inter-agent communication. A controller/supervisor loop constantly reconciles desired state to running state.

The repository shows active community engagement with 258 issues and 225 pull requests. Installation is straightforward via Homebrew (`brew install gastownhall/gascity/gascity`), and the project provides extensive documentation including tutorials, migration guides from Gas Town, and contribution guidelines. Gas City represents the maturation of the multi-agent coding workflow concept from a solo experiment into a community infrastructure project.
