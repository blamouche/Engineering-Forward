# Don't answer the first question

**Source:** https://lalitm.com/post/dont-answer-the-first-question
**Date:** 2026-05-16

## Summary

Lalit Maganti (Perfetto engineer) articulates a golden rule for engineers building tools: don't answer the first version of a user's question. Going beyond the XY problem, he argues the confusion behind a wrong question is an opening for deeper value creation.

His diagnostic framework:
- Have I seen this before?
- Does the question sound reasonable compared to others?
- Does it fit the shape of the tool, or is the user fighting the architecture?

Three resolution paths:
1. **Missing philosophy** — Users don't understand the tool's design principles. Education is part of the job.
2. **Hidden right path** — The tool already solves the problem, but the user doesn't see how. Example: Perfetto supports periodic trace snapshots, eliminating the need for trace splitting.
3. **Product needs to change** — Occasionally reveals genuinely missing functionality. But Maganti advocates waiting until multiple teams express the same need, citing painful experience with premature ad-hoc UI customization that created intractable technical debt.
